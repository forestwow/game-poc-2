# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

The Understudies is a prototype of a short roguelite for PC: a stage magician defends a box office, and every act played leaves behind an understudy that replays the route the player ran. `docs/vision.md` is the design; `docs/plan-prototype.md` is the plan, the decisions that settle the vision's open points, and the ticket list. Read the plan before changing a rule: where the two disagree, the plan is the later decision.

## Commands

All commands run from the repository root. `global.json` names the .NET SDK (10.0.1xx); warnings are errors.

```bash
dotnet build Understudies.sln --configuration Release                     # CI runs this first: `dotnet test` alone never compiles the game
dotnet test Understudies.sln --configuration Release                      # then this
dotnet test tests/Understudies.Core.Tests --filter "FullyQualifiedName~RngTests"   # one class or test
dotnet test tests/Understudies.Core.Tests --configuration Release --filter "FullyQualifiedName~ScriptedPlayersTests.PrintTheGuardsTable" --logger "console;verbosity=detailed"   # the scripted players' table: `[Explicit]`, so it runs only when named itself, and prints only with that logger
dotnet run --project src/Understudies.Game                                # play: the game opens on its main menu; "Perform" opens the poster of the newest night the player's progress has opened, and a press there raises the curtain; Esc in a show or on the poster goes back to the menu, Esc on the menu quits
dotnet run --project src/Understudies.Game -- --night 10                  # the way round the gates: that night's page alone is on the poster, and the progress file is neither read nor written. The last two words of any command line: with --capture it is that night's frame
dotnet run --project src/Understudies.Game -- --capture /tmp/frame.png --ticks 39570  # no play: the doors player of the guard plays for that many ticks (every act's curtain of sixty counted, a card taking none), the frame is saved and the game exits. The console says the tick each encore, program and the ovation is reached on; on the committed numbers act n begins on tick 4560 × (n − 1), and the show is played to its ovation on tick 45600. With no --night a capture plays tuning.json as it is, and no capture reads or writes the progress
dotnet run --project src/Understudies.Game -- --capture /tmp/menu.png --menu          # the main menu's frame: no show is played for it
dotnet run --project src/Understudies.Game -- --capture /tmp/poster.png --poster 2    # the poster's page of that night, for a player with no progress: night 1's is open and every other is the shut page. With `--night n` after it (the same n) it is that night's open page
```

## Architecture

Three projects, with one-way dependencies: **Core** ← **Game** and **Core.Tests**. (The game also compiles one source file of the tests, `ScriptedPlayers.cs`, for the capture.)

- `src/Understudies.Core` is the game's rules, with no reference to MonoGame. `Simulation` owns the state and advances it one tick at a time from the magician's input of that tick; everything else reads the state and the events of the last tick (`Simulation.Events`, whose kinds `TickEventKind` lists; the next `Step` starts the list afresh, so whoever is driven by it reads it after every tick). A `TickEvent` is a kind and a place, and it says who: `Thrower` for a `Throw`, a `Hit`, a `Kill` and a `Burst` (`TickEvent.TheMagician`, or an understudy by its place in `Simulation.Understudies`), and `CriticId` for a `Hit`, a `Kill` and an `ApplauseDropped` (`TickEvent.NoCritic` for the rest). A `Burst` (plan T25) is told at the critic a card struck, after that strike's own event and before a `Hit` or a `Kill` for each critic the burst hurt. An event is not state and none is in the hash, nor is which understudy threw a `ThrownCard` (`ThrownCard.Thrower`) while no rule reads it. The accumulator clock that turns frame time into whole ticks lives here too, where it can be tested. The same seed and inputs are meant to give the same result on every machine (a pinned state hash checks it across two, plan T19), so:
  - positions are `System.Numerics.Vector2` in world units, and the only arithmetic is + − × ÷ and the square root: no trigonometry;
  - (0, 0) is the stage's top-left corner and y grows downward. The top of the stage is the back wall: the floor starts at `stageFloorTop`, the magician's whole circle is kept on the floor, and `Tuning.Parse` refuses a stage door above it. **A stage door** (`stageDoors`, plan T49) is a point of the floor and runs half of `stageDoorWidth` to either side of it along the stage's width, wherever it is: there is no door "in a side edge", the two side doors stand a door's half in from the edge (1.5 and 46.5 of 48), and `Tuning.Parse` refuses one that reaches past a side. Whoever enters does so on the door's own line with its whole circle within the door's width (`LetACriticIn`: the room for its middle is the width less twice its kind's radius, and a kind wider than its door enters at the door's middle), so nobody is first seen half outside the stage. **And a critic is kept on the stage** (plan T49, after its review), in `WalkTheCritics` right after its step, where its place is last changed in a tick: its whole circle within the stage's two sides, and its middle no higher than `stageFloorTop` and no lower than the stage's bottom edge (the middle and not the circle there, since the back door lets a critic in with its middle on the floor's top). A crowd that enters on one tick is still pushed apart wider than its door, and what was thrown out of the stage stands against its edge instead. So a test whose critics stand above the floor's top or nearer a side than their radius gives its own tuning a floor that starts at 0, or a door further in. A test whose scene stands in the stage's top edge gives its own tuning a floor that starts at 0;
  - randomness comes only from `Randomness/Rng` (SplitMix64), never `System.Random`: the simulation draws from the seed its creator gives it (the game takes a played show's seed from the clock, and a capture's is fixed), each purpose from a stream of its own (`Rng.ForStream`, `RngStream`). A new purpose gets a new number, and no number is ever changed or given to another;
  - who enters when is planned once, when a `Simulation` is made: `Waves.Plan` buys each act's critics from `enemyKinds` with the act's budget and gives each a tick of the act and one of the doors open in it (`Simulation.Plan`, `ActEntries`, `ActEntriesMade`, `DoorIsOpen`). The budget is `firstActBudget`, `budgetGrowthPerAct` more in the second act, and that step bigger by `budgetGrowthRise` in every act after it (plan decision 27). The entries are spread evenly over the act, and then a share of them (`waveBurstShare`, picked evenly down the list) is moved to the last moment of a crowd before its own tick, a crowd every `waveBurstTime` seconds from the act's first tick: nothing more is drawn for a crowd, and with no share or no time the plan is the plan without crowds. A reload of the tuning does not plan it again. A critic's own numbers are its kind's (`EnemyKind`), which a `Critic` and a `PlannedEntry` name by its place in the list: the critic is the first kind, the stagehand the second (from act four, fast, never turns on the magician) the rival's understudy the third (plan T29: from act four, slow, wide, never turns, tougher by the act) and the headliner the fourth (plans T41 and T46, decision 32: from act eight, as slow and as wide, never turns, 30 hit points and 15 more an act, a strike of three, sixteen an act and none by the draw, and an understudy's card takes three in a hundred of its damage off it: the late acts' threat, few, each an event, and the magician's own to fell), and the view and the scripted players' instrument know the four by those places and `Shows` the first three. **Two numbers of a kind are plan T46's.** `inAnAct`: every act from the kind's `fromAct` has that many of it whatever is drawn: `Waves.Buy` pays for them first (as many as the act can afford), draws nothing for them, and when the act's draw is over sets each somewhere in a stretch of the buying order of its own, the last first, so sixteen are one to each sixteenth of the buying order: not of the clock, since the crowds move every fourth entry, headliners among them, and two or three enter on one tick in about half the acts (plan T46 has the count; whether such a kind should be exempt from the crowds is the owner's open question there, and is not built); a kind with a `weight` of 0 is never drawn, which is the headliner, and with `inAnAct` at 0 a kind is only drawn for. A weight could not make a kind that rare: the weights are whole numbers and `Rng.NextInt` rejects and takes a remainder, so multiplying the other kinds' weights draws every act from the fourth again. `understudyDamageShare`: what an understudy's card, and its burst, takes off a critic of the kind is this share of its damage (1 for the first three kinds), in `Hurt`, from the tuning of now; the magician's card takes all of it. Neither is state. Every enemy on the stage is a `Critic`, whatever its kind. A strike on the box office takes the striker's own kind's `strikeDamage` (there is no one number for all: the rival's and the headliner's are three times the critic's); a touch on the magician is still `criticTouchDamage` for every kind that turns. The push-apart knows no weight: two overlapping circles are moved half the overlap each whatever their radii, so a rival shoulders nobody aside harder than it is shouldered: its width only keeps the others further from its middle. An enemy enters with its kind's `hitPoints` and `hitPointsPerAct` more for every act after the kind's `fromAct` (nothing for the critic and the stagehand): worked out in `LetACriticIn` from the act's number and the tuning of now and kept as the critic's own hit points, so it is no new state, and a reload counts for whoever enters next. A kind an act may not buy yet takes no part in that act's draws, so a kind added with a later `fromAct` leaves the earlier acts' plans as they were, entry for entry, and a kind with a number for an act draws only in the acts that have it, after their own buying, which leaves them so too (a test holds both for the committed kinds); A test of another rule says exactly who enters through the constructor that takes a plan, with the helpers of `tests/Understudies.Core.Tests/Shows.cs`;
  - the simulation never iterates a `Dictionary` or a `HashSet` and never reads a clock;
  - a performance is `actsInPerformance` acts of `actLength` seconds. `Simulation.Phase` says where it stands: an act is played, it stands for an encore, its program is up, it is between two acts, it has ended in the ovation, or the show has closed (only the box office's fall closes it). `Step` changes the state only in an act, whose timer (`ActTicksLeft`) is counted last in the tick, and in an encore and a program, where it counts the offer's time and nothing else; in the other three it empties the events and nothing else. Between two acts the world stands until `GoOn`, which begins the next act with the magician whole and on its mark, makes the act just over an understudy and leaves everything else as it was. A test whose scene must outlast the committed act gives its own tuning a longer one;
  - the magician's fall does not end the act. From the blow that fells it (`MagicianHasFallen`, one `MagicianFell` event) to the next `GoOn` it takes no input, does not throw, and no critic turns on it; the recording of the act stops there, so that act's understudy leaves the stage (`Understudy.IsOnStage`) after the tick of the fall in every later act. The tick of the act is a count of its own (`_actTicksPlayed`), never the length of the recording;
  - an act is recorded as places, not inputs (plan decision 6): the magician's position after each tick (`Understudy.Route`), the tick and place of each Vanish, the self cards the act began with, and the tick and card of each encore taken in it (plan T24), and nothing else (no facing). An encore's tick is the act's count (`_actTicksPlayed`) while the encore is read, which is the number of the first tick the magician plays with the card. An `Understudy` (`Simulation.Understudies`, in the order of their acts) stands on `Route[tick]` and has the cards the magician played that tick with (`Understudy.Cards`: those its act began with and those of the encores recorded by that tick, worked out afresh in `Place` on every tick, so it throws on the tick of an encore as the magician did, and under an act's curtain it has only the first); before an act's first tick it stands on `Route[0]` with its throw ready, and when its route is shorter than the act it is off the stage (`IsOnStage`) for the rest of it. In a tick the understudies take their places right after the magician moves, each leaving a cloud on a recorded Vanish's tick (no `Vanish` event: that is the magician's own); then the cards fly, the critics walk, the magician throws and then each understudy in the order of their acts, all through the one `ThrowACard`, and a critic enters. A card is thrown ahead of its target, at where the two meet if the target repeats its last step (`Position - PreviousPosition`, made earlier in the same tick, so nothing of an older tick is read), and flies straight, unless its thrower's cards turn it (below); the `ponytail:` comment there says what that misses. `ThrownCard.ThrownByMagician` says who threw a card. No rule for critics, clouds or cards looks at an understudy;
  - applause is the rule against standing by the box office (vision §4, plan decisions 26 and 27). A critic that falls to a card with `ThrownCard.ThrownByMagician` leaves one `Applause` where it fell (`Simulation.ApplauseOnTheFloor`, `ApplauseDropped` after the `Kill`); an understudy's card leaves none, whoever hurt the critic before, and no card does where the critic falls nearer than `applauseBoxOfficeRadius` to the box office's middle: the critic's place, never the magician's, and a fall exactly on the radius leaves its piece. A test of another rule whose scene falls by the box office gives its tuning a radius of nothing. A piece fades at the start of a tick, as a cloud thins, and lies for `applauseTime`. Only a magician that stands picks one up, right after it moves, within its radius and `applausePickUpReach` (`ApplausePickedUp`): no rule lets an understudy. `ActApplause` counts the act's pieces, and `EncoreApplause` those of them that no encore has been paid with yet. `GoOn` clears the floor and both counts: applause is never banked;
  - the cards (plan decisions 20 and 26). **The encore** is where the magician gets its self cards. It costs `EncoreCost` pieces: `encoreFirstCost`, and `encoreCostGrowth` more for every one of `EncoresTaken`, which counts through the performance. When a tick of an act is over, the act has time left, the magician has not fallen and `EncoreApplause` has reached the cost, the phase is `Phase.Encore`: `Simulation.Offer` has three different self cards, the leftmost first, drawn from the stream `RngStream.Encore` (fewer under the limit on copies, below), and `Step` counts `OfferTicksLeft` down from `encoreTime` and does nothing else (the act's timer stands, no input is taken or kept). `Pick(place)` gives the magician the card at once, takes the cost from `EncoreApplause` (what is over stays, and opens the next encore when the next tick of the act is over), counts one more encore, and the act goes on; the tick that ends the encore's time is `Pick(0)`. A piece picked up on an act's last tick opens nothing. **The program** is where the chorus card comes from, and it is paid for by an encore: on the last tick of an act in which at least one encore was taken (`ActEncores`, which `GoOn` clears: an earlier act's encore does not count), and which has another after it and has not closed the show, the offer is the chorus card alone, the phase is `Phase.Program`, and `Step` counts `OfferTicksLeft` down from `programTime`. An act with no encore has no program and is between two acts at once: a player that picks up no applause gets nothing for its chorus either. `Pick(0)` or the end of that time takes it, which leaves the stage between two acts; a pick while nothing is offered or for a place the offer does not have does nothing, and `GoOn` does nothing in an encore or a program. The state is counts and never numbers: `SelfCards` is how many of each of the eight self cards somebody has, `MagicianCards` the magician's, `Understudy.Cards` those that understudy has on this tick of the act (what its act began with, kept apart in `_recordingCards` while the act is played, and each card of that act's encores from its tick on, kept in `_encores`; the Vanish cooldown card changes nothing for an understudy, whose Vanishes are recorded ticks), and `ChorusCards` how many chorus cards were taken. The numbers are worked out from the tuning of now where they are used: in the one `ThrowACard` (range, damage, the time to the next throw and how many cards, each at a critic of its own, the nearest first, and none for a critic that is not there; the chorus damage for an understudy only) and in `VanishCooldownTicks`. A `ThrownCard` carries the damage it was thrown with. The smaller rule was taken for one more card: no spread when there is one target. **The limit on copies** (plan T41, decision 31): the magician holds at most `cardMaxCopies` (3) of a self card; with nothing there is no limit. `OfferAnEncore` leaves every kind it holds that many of out of the pile it draws from, so an encore offers two cards or one when no more kinds are left, and the chorus card alone when none is. That chorus card is taken as an encore's card is: the cost, `EncoresTaken`, `ActEncores` (so its act has a program, which offers its chorus card as before), `ChorusCards`, and a recorded encore of the act that gives its understudy nothing on its tick, since a chorus card is nobody's own (`SelfCards.With`). No state was added. An understudy's cards follow from the magician's, so none holds more. `SelfCards.Of` says how many of a card somebody has. The chorus card has no limit. A test that takes more than three of a card gives its tuning a `CardMaxCopies` of nothing, as `CardTests.Scene` does; the limit's own tests reach it in one act with `CardTests.InAnEncoreAfter`. **Three self cards change what a thrown card does when it strikes** (plan T25, decision 29), for an understudy as for the magician, since both throw through `ThrowACard` and every card flies through `FlyTheCards`. A card carries what it needs, worked out at the throw as its damage is: `PierceLoss` (what a strike takes off `Damage`: all of it for a thrower with no pierce card, so that its first strike spends it, and `cardPierceLoss` over the thrower's pierce cards otherwise), `TurnsLeft` (the thrower's ricochet cards), `BurstShare` (`cardBurstShare` times the thrower's burst cards) and `Struck`, the ids of the critics it has struck. In one tick's step a card strikes every critic it comes to that it has not struck, the first first. A strike is `Hurt` (the one place a card takes hit points, fells, reports and leaves applause, by the rule above and at the place of whoever fell; an understudy's card takes the struck kind's `understudyDamageShare` of the damage there, plan T46, by its strike and by its burst alike), then the burst: a `Burst` event and `Hurt` with the share of the card's damage of that strike for every other critic whose middle is within `cardBurstRadius` of the struck one's, one the card went through before among them; a burst strikes nobody for the card, which may strike them yet. Then **the turn comes before the pierce**: with a turn left and a critic it has not struck within `cardRicochetReach` of the struck one's middle (the nearest; of two as near the one that entered first), the card turns to it where it touched the circle, loses nothing, has as far as that critic's middle left to fly, or the reach when that is more, is aimed at where that critic stands (no lead: a `ponytail:` there) and flies the rest of its step the new way; `ThrownFrom`, which only the view reads, becomes the place of the turn. Otherwise the strike takes `PierceLoss` off the card, which is spent when less than `Simulation.SpentBelow` is left (the losses are a sum of floats, and a residue must not strike) and else goes on through. A turn nobody is in reach for is kept. The reach and the radius are the tuning's of now. A test of these rules arranges its critics with `CardTests.WithACrowd`. A test of another rule whose act picks up as much applause as an encore costs meets an encore, and then a program: it gives its tuning an `EncoreFirstCost` nobody can pay, or an `ApplauseTime` of nothing, or calls `Pick(0)` before every tick and before `GoOn`. A test that needs a certain card looks for a seed whose encores offer it (`CardTests.SeedWhoseEncores`): what an encore offers follows from the seed and from how many encores were opened before it alone, until a kind is out of the pile by the limit on copies: from then it follows from the cards taken as well. The stream `RngStream.Program` is drawn from no more;
  - `Simulation.ComputeStateHash` is an FNV-1a hash of everything that decides what happens next. State added to the simulation is added to it in the same change, a `float` by its bits; what only the view reads (the positions before the last tick, the events, where a card was thrown from or last turned) stays out. Each of the four things a thrown card carries since plan T25 has a test that tells it apart and fails without it: the loss and the burst's share by two tunings and one card in the air, a turn left by a card that turned to a critic straight ahead, the critics struck by a critic that enters where the card is. It walks every recording whole, so it is for tests and scripted players and not for every frame;
  - a time in `tuning.json` is in seconds and a rule counts it in whole ticks;
  - `tuning.json` at the repository root is the only place a rule's number lives (the tick rate is the one constant in code; the juice's numbers decide no rule and are constants in the view). `Tuning` is the record parsed from it, and `Simulation` is given one by whoever creates it. A new number is a new member of `Tuning` and a new key in the file: an unknown key and a missing key are both refused, at any depth.
- `src/Understudies.Game` is the MonoGame (DesktopGL) layer: input, drawing, sound. It holds no rules: it feeds the simulation the player's input each tick and draws what the simulation reports, with positions interpolated between the last two ticks. There is no content pipeline. The figures (the magician, the critic, the stagehand, the rival's understudy, the box office) are pixel-art sprites read at start-up with `Texture2D.FromFile` from `art/ludo/sprites/` (`ReadSheet`; found as `tuning.json` is, and copied beside the built game), and so is the set (plan T07d): the floor's boards and the back wall's curtain, two pictures laid side by side by `Lay` in a batch that lets a picture go round, the three stage doors (a shut picture and a lit one, by `DoorIsOpen`; a door's picture stands with its foot on the line its critics enter on, `DoorSill` below it, so whoever enters stands in the lit frame with its feet on the sill, and the door at the back wall stands up in the curtain with its eye cut by the window's top: plan T49, and the view does not move a door's picture sideways from where the tuning has the door) and the footlights along the front edge, which are drawn by `DrawFigure` as a figure is: the doors under the figures, so that a door hides nobody, and the footlights over everything on the stage and over the wash, whole in an act, at `FootlightsInAnEncore` (a half) while an encore is read and at `FootlightsBetweenActs` (0.35) in the program and between two acts. The set as the design has it (plan T42): the boards are dimmed with `BoardsDim`, a gold line (`GoldLine`, four screen pixels at 1280 wide) lies along their top under the curtain, and a stage that stands for an offer is washed with black at `ProgramDim`, six tenths. Everything else is shapes. A walking figure is a sheet of three rows of three frames for each of three views (toward the viewer, away, and to the right, mirrored for the left); the stagehand and the rival's understudy (`rival-down.png`, frames of 60 × 68: a cut-out, as tall as the magician and wider) have the first view alone and are never mirrored. `FigureOf` says which figure a kind is drawn as, by the kind's place in `enemyKinds`: the headliner, the fourth, is the rival's cut-out with a red wash (`WashOf`, `HeadlinerWash`, through `DrawFigure`'s `tint`, standing and fallen, and under the pallor when it is stunned: `pale` is washed over a tint and does not replace it) until it has a picture of its own, with a small bar under its feet in the same red for its hit points (plan T46: `FillBar`, as the box office's; full is what a headliner enters with in the act that is played, a `ponytail:` there), and a kind past the fourth is drawn as a stagehand; `DrawFigure` picks the view from where the figure goes and the frame from the view's own clock, quicker for a quicker figure (the kind's speed over `WalkReferenceSpeed`, kept within bounds), and draws it unsmoothed and from a whole screen pixel, to one of **two measures**, both in units whatever the window (plan T42; the window opens at 1280 × 720, and a capture is that size). The set's is `SetPixelsPerUnit` (64 sprite pixels are three units), for the curtain, the doors, the box office and the footlights, so the curtain is three units, the box office four and a door three at every size. The walking figures' is `FiguresMeasure` times that (`FigurePixel`), for the magician, its understudies, the critic, the stagehand and the rival (`figure <= Figure.Rival`: the walking figures are first in the enum), with their flash, wash and fallen body, and the two bursts. **`FiguresMeasure` is committed at 1**: a figure as large against the stage as before T42 (the magician 3.09 units), which is one screen pixel to a sprite pixel at 1024 wide and one and a quarter at 1280. At `1.6f` it is the design's (4.95 units, two screen pixels at 1280): built, its frames in `art/frames/s2-design`, and the owner has not chosen between the two (plan T42), so nothing is built on either size. A sprite pixel is a whole number of screen pixels only where the window makes it one (a figure's is snapped when it is within `WholeWithin`, a twentieth of a screen pixel, of one): elsewhere the pixels are uneven, every fourth two screen pixels at 1.25 (a `ponytail:` in `DrawFigure`). The stage's corner is rounded to a whole screen pixel after the shake, or the uneven pixels would shimmer. The boards alone are laid at a whole number of screen pixels (`FloorMeasure`, two at 1280: they have no footprint to keep). What is at a figure's chest or over its head is `FiguresMeasure` times what it was (`ThrownCardLift`, `FlickSize`, the juice's `ScrapLift` and `KillFlashRadius`, `BoxOfficeBarLift`), which is the figure's drawn size at every window since the figure is in units; the caption and an understudy's mark stand over `MagicianTall`. The magician's pips and its Vanish's bar are the HUD's size and do not follow the measure (below). No footprint, range or radius follows the measure, and nothing clips a figure: at 1.6 it stands over the curtain at the foot of the back wall and out of the stage's top and sides at a door. The flash is a white copy of the sprite drawn over it, an understudy is the magician's shape filled with its act's colour with the magician's sprite over that (`cardboard`), the magician itself is washed pale and part see-through while `MagicianIsInvulnerable` (the Vanish's moment), and a standing figure has a shadow. `art/prompt-guide.md` is the recipe a new figure is made by. What makes a blow felt (flashes, scraps, fading bodies, the shake, the hit-stop, and the cards' effects of plan T22: a flick at a throwing hand, a burst where a card strikes and one where its critic falls, the two bursts sheets played through once; the ring of plan T25's burst card, drawn from the `Burst` event as short stretches round the struck critic's place on the floor, opening to `cardBurstRadius` and dimmer for an understudy's card (`Effect.Ring`, `Effect.UnderstudyRing`); and a puff of scraps at an understudy that gains a card of its act's encores, which no event reports: `Feed` sees that it has more cards than a tick before; the critic that flashes is the one a `Hit` names, kept by its id until its `Kill`; a body lies as the kind it was, which the juice keeps for every critic on the stage by its id, since a `Kill` names a critic that is gone by then; and an understudy's throw is a smaller, dimmer flick in its card's face, `Effect.UnderstudyFlick`, so that the past is told from the present) is the view's own state, in `Juice.cs`: `UnderstudiesGame.Tick` feeds it the simulation after every tick (whatever else the events drive, the sound for one, is fed there too), the frame's time advances it, and the drawing asks it what to add. The capture mode feeds and advances it the same way, a sixtieth of a second a tick. It is advanced in every phase: between two acts the simulation stands and the juice still settles. The shake is a function of the juice's time and draws nothing from `Random`: `ShakesPerSecond` places a second, the same at every frame rate and in a capture. The kill's burst has a pale disc under it for its first half (`KillFlash...`), without which its black ink is lost on the boards. Its numbers are named constants at the top of that file. A figure is drawn by `DrawFigure` alone, which is asked for a flash, a fallen pose and an opacity: nothing paints over a figure with a shape of its own, so the juice holds whatever a figure is drawn from. Text is `FontStashSharp.MonoGame` over the repository's own font files (plan decision 30, T40), in `fonts/` with each family's `OFL.txt`: found as the sprites are (the repository's own when run from its root, the copy the project file puts beside the executable otherwise, the `.ttf` files and the licence texts), and a folder counts only when it has every file of `FaceFiles`, which `Program.cs` checks before a window opens: without one of them the game names it on the console and does not start. - `tuning.json` is copied by the project files beside the tests and beside the built game. The tests read that copy through `CommittedTuning`, so a test never carries its own numbers. The game reads `tuning.json` in the current directory first (the committed file itself, as commands run from the root) and the copy beside the executable otherwise, and `nights.json` the same way (`TuningFile.Read` gives both or neither, and refuses nights that are none or that do not all compose); F5 reads both again while the game runs and the numbers are the played night's from the next tick: the planned entries stay, and nights without the night that is played change nothing.
- `nights.json` at the repository root is the ladder's nights (plan T51, decision 33): a list in the order of their numbers, each a `night` and the keys it overrides, and a night with its number alone is the plain night. It is copied beside the tests and beside the built game as `tuning.json` is; the tests read it through `CommittedNights` (in `CommittedTuning.cs`), and the game plays the night its menu has chosen (plan T54). `src/Understudies.Core/Night.cs` is all of it. `Night.Parse` refuses as `Tuning.Parse` does (an unknown key, a key twice, no number, a night twice or out of order, a `kindsAllowed` that is empty or has a null in it are a `JsonException` that names the place), with two differences: every key but the number may be left out, and a file of no nights (`[]`) is read, every number then being refused by `Compose`. `Night.Compose(plain, nights, number)` is a pure function to the night's `Tuning`, which is what a `Simulation` is given: no rule knows of a night, and a night's new key is composed into the tuning, never read by `Simulation` or `Waves`. A night that overrides nothing composes to the plain tuning itself (a test holds night 10 to that, by the record's equality: the lists are the same lists); a number the file does not have is refused (`ArgumentOutOfRangeException`), so no night is played as the plain night by default. The keys are `actsInPerformance` and `waveBurstShare` (the tuning's own), `budgetScale` and `kindsAllowed`, and `name` (plan T55), the night's name on its poster: it overrides nothing, `Compose` never looks at it, and it may be left out as every other key may (the poster then has "Night 3"), since a night with its number alone must stay the plain night; one that is there has words in it. A key is added by the night that first needs it, none before, and to the instrument's `NightKeys`. `budgetScale` is a decimal that multiplies `firstActBudget`, `budgetGrowthPerAct` and `budgetGrowthRise`, each rounded to the nearest whole number and a half up, so that every act has the scale's share of the plain act's budget (exactly, on the committed numbers); a kind's `inAnAct` is not scaled, since it is paid out of that budget. A kind not named in `kindsAllowed` keeps its place in `enemyKinds` (a planned entry and the view name a kind by its place: the list is never shortened or reordered) with no `weight` and no `inAnAct`, which `Waves` already never buys and never draws for; a name the tuning does not have is refused, at the composition and not by the parser, so a test composes every committed night. The guard reads the plain tuning alone: a night's own assertion is a new ordinary test with its own floors, and a scale is a number of the balance, searched by the seeds' rule (plan, "The ladder", L2).
- **The progress** (plan T54, decision 33) is `src/Understudies.Core/Progress.cs`: the nights the player has played, each its number, the best act a show of it was in and whether it was won. It is in Core for its rules and its tests and is no part of a show: **`Simulation` never reads it, it is in no hash**, and a new thing remembered goes there and never into the simulation. `Progress.Parse` is as strict as the tuning's (a key unknown, missing or twice, another `Version`, a night or an act below 1, a night twice or out of order); `With` is one more show; `GateOf(night)` is which gate a night has (`Gate.Played`, `ActReachedOrWon`, `Won`), the one rule `Unlocked` opens by and the poster puts in words; `Unlocked(nights)` is the gates: the first night of `nights.json` is open, another is open when the night before it in the file has passed its gate, read by that earlier night's number (played, before night 6; act five reached or won, from 6; won, from 16: three constants there, and `ActThatUnlocks` at 5 is "a show that closed in act five has reached it"), and a night that was played is open. `Load(path, out notKept)` never throws and never stops the game: no file or no folder is no progress, and a file that is not the progress (damaged, empty, an older version) is moved aside to its name with `.damaged` (one kept, the last) and read as none; **`notKept` is a reason when the file is there and is not this game's to write over** (it could not be read, it could not be moved aside, or it has a higher `Version`, which is a newer game's and is not called damaged), and whoever is given one saves nothing to that path in the run: a valid file that could not be read for a moment was once replaced by the first save. `Save(path)` writes a `.tmp` beside the file and moves it over, which a test holds (a `ponytail:` there: no flush before the rename, one `.tmp` name for two games at once). The tests that need a file's Unix mode are ignored on Windows. Every method that touches a file takes its path, and **no test goes near the player's folder** (`ProgressTests` make a folder of their own). A change to the file's shape counts `Version` one more and says what an older file becomes.

## How the work runs

- One ticket of `docs/plan-prototype.md` is one branch (`tNN-short-name`) and one small pull request into `main`, whose title starts with the ticket id (`T04: ...`). Tickets are taken in order.
- Work in a git worktree; the owner's checkout stays on `main`.
- Write the test first for every rule in Core. The view and the juice have no tests: they are judged by eye at the plan's stops, and by a captured frame in review.
- Before a merge, a separate agent with a clean context reviews the pull request with the `mattpocock-skills:code-review` skill (fixed point `main`; the spec is the ticket in the plan) and the `ponytail:ponytail-review` skill. Fix or answer what it finds, wait for green CI, then merge.
- The plan's stops are where the owner plays and judges. The loop does not wait at a stop: it announces it and goes on.
- Build the smallest thing the ticket asks for: no abstraction, option or layer for a later ticket. Mark a deliberate shortcut that has a known ceiling with a `ponytail:` comment naming the ceiling.
- Everything in the repository is in English. There is no study journal in this project.
