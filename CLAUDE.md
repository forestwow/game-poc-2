# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

The Understudies is a prototype of a short roguelite for PC: a stage magician defends a box office, and every act played leaves behind an understudy that replays the route the player ran. `docs/vision.md` is the design; `docs/plan-prototype.md` is the plan, the decisions that settle the vision's open points, and the ticket list. Read the plan before changing a rule: where the two disagree, the plan is the later decision.

## Commands

All commands run from the repository root. `global.json` names the .NET SDK (10.0.1xx); warnings are errors.

```bash
dotnet build Understudies.sln --configuration Release                     # CI runs this first: `dotnet test` alone never compiles the game
dotnet test Understudies.sln --configuration Release                      # then this
dotnet test tests/Understudies.Core.Tests --filter "FullyQualifiedName~RngTests"   # one class or test
dotnet test tests/Understudies.Core.Tests --configuration Release --filter "FullyQualifiedName~ScriptedPlayersTests.PrintTheGuardsTable" --logger "console;verbosity=detailed"   # the scripted players' table: `[Explicit]`, so it runs only when named itself, and prints only with that logger
dotnet run --project src/Understudies.Game                                # play; Esc quits
dotnet run --project src/Understudies.Game -- --capture /tmp/frame.png --ticks 39570  # no play: the doors player of the guard plays for that many ticks (every act's curtain of sixty counted, a card taking none), the frame is saved and the game exits. The console says the tick each encore, program and the ovation is reached on; on the committed numbers act n begins on tick 4560 × (n − 1), and the show is played to its ovation on tick 45600
```

## Architecture

Three projects, with one-way dependencies: **Core** ← **Game** and **Core.Tests**. (The game also compiles one source file of the tests, `ScriptedPlayers.cs`, for the capture.)

- `src/Understudies.Core` is the game's rules, with no reference to MonoGame. `Simulation` owns the state and advances it one tick at a time from the magician's input of that tick; everything else reads the state and the events of the last tick (`Simulation.Events`, whose kinds `TickEventKind` lists; the next `Step` starts the list afresh, so whoever is driven by it reads it after every tick). A `TickEvent` is a kind and a place, and it says who: `Thrower` for a `Throw`, a `Hit`, a `Kill` and a `Burst` (`TickEvent.TheMagician`, or an understudy by its place in `Simulation.Understudies`), and `CriticId` for a `Hit`, a `Kill` and an `ApplauseDropped` (`TickEvent.NoCritic` for the rest). A `Burst` (plan T25) is told at the critic a card struck, after that strike's own event and before a `Hit` or a `Kill` for each critic the burst hurt. An event is not state and none is in the hash, nor is which understudy threw a `ThrownCard` (`ThrownCard.Thrower`) while no rule reads it. The accumulator clock that turns frame time into whole ticks lives here too, where it can be tested. The same seed and inputs are meant to give the same result on every machine (a pinned state hash checks it across two, plan T19), so:
  - positions are `System.Numerics.Vector2` in world units, and the only arithmetic is + − × ÷ and the square root: no trigonometry;
  - (0, 0) is the stage's top-left corner and y grows downward. The top of the stage is the back wall: the floor starts at `stageFloorTop`, the magician's whole circle is kept on the floor, and `Tuning.Parse` refuses a stage door above it. Critics are kept on the floor by no rule. A test whose scene stands in the stage's top edge gives its own tuning a floor that starts at 0;
  - randomness comes only from `Randomness/Rng` (SplitMix64), never `System.Random`: the simulation draws from the seed its creator gives it (the game takes a played show's seed from the clock, and a capture's is fixed), each purpose from a stream of its own (`Rng.ForStream`, `RngStream`). A new purpose gets a new number, and no number is ever changed or given to another;
  - who enters when is planned once, when a `Simulation` is made: `Waves.Plan` buys each act's critics from `enemyKinds` with the act's budget and gives each a tick of the act and one of the doors open in it (`Simulation.Plan`, `ActEntries`, `ActEntriesMade`, `DoorIsOpen`). The budget is `firstActBudget`, `budgetGrowthPerAct` more in the second act, and that step bigger by `budgetGrowthRise` in every act after it (plan decision 27). The entries are spread evenly over the act, and then a share of them (`waveBurstShare`, picked evenly down the list) is moved to the last moment of a crowd before its own tick, a crowd every `waveBurstTime` seconds from the act's first tick: nothing more is drawn for a crowd, and with no share or no time the plan is the plan without crowds. A reload of the tuning does not plan it again. A critic's own numbers are its kind's (`EnemyKind`), which a `Critic` and a `PlannedEntry` name by its place in the list: the critic is the first kind, the stagehand the second (from act four, fast, never turns on the magician) and the rival's understudy the third (plan T29: from act four, slow, wide, never turns, tougher by the act), and the view and `Shows` know the three by those places. Every enemy on the stage is a `Critic`, whatever its kind. A strike on the box office takes the striker's own kind's `strikeDamage` (there is no one number for all: the rival's is three times the critic's); a touch on the magician is still `criticTouchDamage` for every kind that turns. The push-apart knows no weight: two overlapping circles are moved half the overlap each whatever their radii, so a rival shoulders nobody aside harder than it is shouldered: its width only keeps the others further from its middle. An enemy enters with its kind's `hitPoints` and `hitPointsPerAct` more for every act after the kind's `fromAct` (nothing for the critic and the stagehand): worked out in `LetACriticIn` from the act's number and the tuning of now and kept as the critic's own hit points, so it is no new state, and a reload counts for whoever enters next. A kind an act may not buy yet takes no part in that act's draws, so a kind added with a later `fromAct` leaves the earlier acts' plans as they were, entry for entry; A test of another rule says exactly who enters through the constructor that takes a plan, with the helpers of `tests/Understudies.Core.Tests/Shows.cs`;
  - the simulation never iterates a `Dictionary` or a `HashSet` and never reads a clock;
  - a performance is `actsInPerformance` acts of `actLength` seconds. `Simulation.Phase` says where it stands: an act is played, it stands for an encore, its program is up, it is between two acts, it has ended in the ovation, or the show has closed (only the box office's fall closes it). `Step` changes the state only in an act, whose timer (`ActTicksLeft`) is counted last in the tick, and in an encore and a program, where it counts the offer's time and nothing else; in the other three it empties the events and nothing else. Between two acts the world stands until `GoOn`, which begins the next act with the magician whole and on its mark, makes the act just over an understudy and leaves everything else as it was. A test whose scene must outlast the committed act gives its own tuning a longer one;
  - the magician's fall does not end the act. From the blow that fells it (`MagicianHasFallen`, one `MagicianFell` event) to the next `GoOn` it takes no input, does not throw, and no critic turns on it; the recording of the act stops there, so that act's understudy leaves the stage (`Understudy.IsOnStage`) after the tick of the fall in every later act. The tick of the act is a count of its own (`_actTicksPlayed`), never the length of the recording;
  - an act is recorded as places, not inputs (plan decision 6): the magician's position after each tick (`Understudy.Route`), the tick and place of each Vanish, the self cards the act began with, and the tick and card of each encore taken in it (plan T24), and nothing else (no facing). An encore's tick is the act's count (`_actTicksPlayed`) while the encore is read, which is the number of the first tick the magician plays with the card. An `Understudy` (`Simulation.Understudies`, in the order of their acts) stands on `Route[tick]` and has the cards the magician played that tick with (`Understudy.Cards`: those its act began with and those of the encores recorded by that tick, worked out afresh in `Place` on every tick, so it throws on the tick of an encore as the magician did, and under an act's curtain it has only the first); before an act's first tick it stands on `Route[0]` with its throw ready, and when its route is shorter than the act it is off the stage (`IsOnStage`) for the rest of it. In a tick the understudies take their places right after the magician moves, each leaving a cloud on a recorded Vanish's tick (no `Vanish` event: that is the magician's own); then the cards fly, the critics walk, the magician throws and then each understudy in the order of their acts, all through the one `ThrowACard`, and a critic enters. A card is thrown ahead of its target, at where the two meet if the target repeats its last step (`Position - PreviousPosition`, made earlier in the same tick, so nothing of an older tick is read), and flies straight, unless its thrower's cards turn it (below); the `ponytail:` comment there says what that misses. `ThrownCard.ThrownByMagician` says who threw a card. No rule for critics, clouds or cards looks at an understudy;
  - applause is the rule against standing by the box office (vision §4, plan decisions 26 and 27). A critic that falls to a card with `ThrownCard.ThrownByMagician` leaves one `Applause` where it fell (`Simulation.ApplauseOnTheFloor`, `ApplauseDropped` after the `Kill`); an understudy's card leaves none, whoever hurt the critic before, and no card does where the critic falls nearer than `applauseBoxOfficeRadius` to the box office's middle: the critic's place, never the magician's, and a fall exactly on the radius leaves its piece. A test of another rule whose scene falls by the box office gives its tuning a radius of nothing. A piece fades at the start of a tick, as a cloud thins, and lies for `applauseTime`. Only a magician that stands picks one up, right after it moves, within its radius and `applausePickUpReach` (`ApplausePickedUp`): no rule lets an understudy. `ActApplause` counts the act's pieces, and `EncoreApplause` those of them that no encore has been paid with yet. `GoOn` clears the floor and both counts: applause is never banked;
  - the cards (plan decisions 20 and 26). **The encore** is where the magician gets its self cards. It costs `EncoreCost` pieces: `encoreFirstCost`, and `encoreCostGrowth` more for every one of `EncoresTaken`, which counts through the performance. When a tick of an act is over, the act has time left, the magician has not fallen and `EncoreApplause` has reached the cost, the phase is `Phase.Encore`: `Simulation.Offer` has three different self cards, the leftmost first, drawn from the stream `RngStream.Encore`, and `Step` counts `OfferTicksLeft` down from `encoreTime` and does nothing else (the act's timer stands, no input is taken or kept). `Pick(place)` gives the magician the card at once, takes the cost from `EncoreApplause` (what is over stays, and opens the next encore when the next tick of the act is over), counts one more encore, and the act goes on; the tick that ends the encore's time is `Pick(0)`. A piece picked up on an act's last tick opens nothing. **The program** is where the chorus card comes from, and it is paid for by an encore: on the last tick of an act in which at least one encore was taken (`ActEncores`, which `GoOn` clears: an earlier act's encore does not count), and which has another after it and has not closed the show, the offer is the chorus card alone, the phase is `Phase.Program`, and `Step` counts `OfferTicksLeft` down from `programTime`. An act with no encore has no program and is between two acts at once: a player that picks up no applause gets nothing for its chorus either. `Pick(0)` or the end of that time takes it, which leaves the stage between two acts; a pick while nothing is offered or for a place the offer does not have does nothing, and `GoOn` does nothing in an encore or a program. The state is counts and never numbers: `SelfCards` is how many of each of the eight self cards somebody has, `MagicianCards` the magician's, `Understudy.Cards` those that understudy has on this tick of the act (what its act began with, kept apart in `_recordingCards` while the act is played, and each card of that act's encores from its tick on, kept in `_encores`; the Vanish cooldown card changes nothing for an understudy, whose Vanishes are recorded ticks), and `ChorusCards` how many chorus cards were taken. The numbers are worked out from the tuning of now where they are used: in the one `ThrowACard` (range, damage, the time to the next throw and how many cards, each at a critic of its own, the nearest first, and none for a critic that is not there; the chorus damage for an understudy only) and in `VanishCooldownTicks`. A `ThrownCard` carries the damage it was thrown with. The smaller rule was taken for one more card: no spread when there is one target. **Three self cards change what a thrown card does when it strikes** (plan T25, decision 29), for an understudy as for the magician, since both throw through `ThrowACard` and every card flies through `FlyTheCards`. A card carries what it needs, worked out at the throw as its damage is: `PierceLoss` (what a strike takes off `Damage`: all of it for a thrower with no pierce card, so that its first strike spends it, and `cardPierceLoss` over the thrower's pierce cards otherwise), `TurnsLeft` (the thrower's ricochet cards), `BurstShare` (`cardBurstShare` times the thrower's burst cards) and `Struck`, the ids of the critics it has struck. In one tick's step a card strikes every critic it comes to that it has not struck, the first first. A strike is `Hurt` (the one place a card takes hit points, fells, reports and leaves applause, by the rule above and at the place of whoever fell), then the burst: a `Burst` event and `Hurt` with the share of the card's damage of that strike for every other critic whose middle is within `cardBurstRadius` of the struck one's, one the card went through before among them; a burst strikes nobody for the card, which may strike them yet. Then **the turn comes before the pierce**: with a turn left and a critic it has not struck within `cardRicochetReach` of the struck one's middle (the nearest; of two as near the one that entered first), the card turns to it where it touched the circle, loses nothing, has as far as that critic's middle left to fly, or the reach when that is more, is aimed at where that critic stands (no lead: a `ponytail:` there) and flies the rest of its step the new way; `ThrownFrom`, which only the view reads, becomes the place of the turn. Otherwise the strike takes `PierceLoss` off the card, which is spent when less than `Simulation.SpentBelow` is left (the losses are a sum of floats, and a residue must not strike) and else goes on through. A turn nobody is in reach for is kept. The reach and the radius are the tuning's of now. A test of these rules arranges its critics with `CardTests.WithACrowd`. A test of another rule whose act picks up as much applause as an encore costs meets an encore, and then a program: it gives its tuning an `EncoreFirstCost` nobody can pay, or an `ApplauseTime` of nothing, or calls `Pick(0)` before every tick and before `GoOn`. A test that needs a certain card looks for a seed whose encores offer it (`CardTests.SeedWhoseEncores`): what an encore offers follows from the seed and from how many encores were opened before it alone. The stream `RngStream.Program` is drawn from no more;
  - `Simulation.ComputeStateHash` is an FNV-1a hash of everything that decides what happens next. State added to the simulation is added to it in the same change, a `float` by its bits; what only the view reads (the positions before the last tick, the events, where a card was thrown from or last turned) stays out. Each of the four things a thrown card carries since plan T25 has a test that tells it apart and fails without it: the loss and the burst's share by two tunings and one card in the air, a turn left by a card that turned to a critic straight ahead, the critics struck by a critic that enters where the card is. It walks every recording whole, so it is for tests and scripted players and not for every frame;
  - a time in `tuning.json` is in seconds and a rule counts it in whole ticks;
  - `tuning.json` at the repository root is the only place a rule's number lives (the tick rate is the one constant in code; the juice's numbers decide no rule and are constants in the view). `Tuning` is the record parsed from it, and `Simulation` is given one by whoever creates it. A new number is a new member of `Tuning` and a new key in the file: an unknown key and a missing key are both refused, at any depth.
- `src/Understudies.Game` is the MonoGame (DesktopGL) layer: input, drawing, sound. It holds no rules: it feeds the simulation the player's input each tick and draws what the simulation reports, with positions interpolated between the last two ticks. There is no content pipeline. The figures (the magician, the critic, the stagehand, the rival's understudy, the box office) are pixel-art sprites read at start-up with `Texture2D.FromFile` from `art/ludo/sprites/` (`ReadSheet`; found as `tuning.json` is, and copied beside the built game), and so is the set (plan T07d): the floor's boards and the back wall's curtain, two pictures laid side by side by `Lay` in a batch that lets a picture go round, the three stage doors (a shut picture and a lit one, by `DoorIsOpen`) and the footlights along the front edge, which are drawn by `DrawFigure` as a figure is: the doors under the figures, so that a door hides nobody, and the footlights over everything on the stage and over the wash, whole in an act, at `FootlightsInAnEncore` (a half) while an encore is read and at `FootlightsBetweenActs` (0.35) in the program and between two acts, where those under the line of what is held (`HeldLines`, written along that edge) are out. The set as the design has it (plan T42): the boards are dimmed with `BoardsDim`, a gold line (`GoldLine`, four screen pixels at 1280 wide) lies along their top under the curtain, and a stage that stands for an offer is washed with black at `ProgramDim`, six tenths. Everything else is shapes. A walking figure is a sheet of three rows of three frames for each of three views (toward the viewer, away, and to the right, mirrored for the left); the stagehand and the rival's understudy (`rival-down.png`, frames of 60 × 68: a cut-out, as tall as the magician and wider) have the first view alone and are never mirrored. `FigureOf` says which figure a kind is drawn as, by the kind's place in `enemyKinds`, and a kind past the third is drawn as a stagehand; `DrawFigure` picks the view from where the figure goes and the frame from the view's own clock, quicker for a quicker figure (the kind's speed over `WalkReferenceSpeed`, kept within bounds), and draws it unsmoothed and from a whole screen pixel, to one of **two measures**, both in units whatever the window (plan T42; the window opens at 1280 × 720, and a capture is that size). The set's is `SetPixelsPerUnit` (64 sprite pixels are three units), for the curtain, the doors, the box office and the footlights, so the curtain is three units, the box office four and a door three at every size. The walking figures' is `FiguresMeasure` times that (`FigurePixel`), for the magician, its understudies, the critic, the stagehand and the rival (`figure <= Figure.Rival`: the walking figures are first in the enum), with their flash, wash and fallen body, and the two bursts. **`FiguresMeasure` is committed at 1**: a figure as large against the stage as before T42 (the magician 3.09 units), which is one screen pixel to a sprite pixel at 1024 wide and one and a quarter at 1280. At `1.6f` it is the design's (4.95 units, two screen pixels at 1280): built, its frames in `art/frames/s2-design`, and the owner has not chosen between the two (plan T42), so nothing is built on either size. A sprite pixel is a whole number of screen pixels only where the window makes it one (a figure's is snapped when it is within `WholeWithin`, a twentieth of a screen pixel, of one): elsewhere the pixels are uneven, every fourth two screen pixels at 1.25 (a `ponytail:` in `DrawFigure`). The stage's corner is rounded to a whole screen pixel after the shake, or the uneven pixels would shimmer. The boards alone are laid at a whole number of screen pixels (`FloorMeasure`, two at 1280: they have no footprint to keep). What is at a figure's chest or over its head is `FiguresMeasure` times what it was (`ThrownCardLift`, `FlickSize`, the juice's `ScrapLift` and `KillFlashRadius`, the magician's two bars, `BoxOfficeBarLift`), which is the figure's drawn size at every window since the figure is in units; the Vanish's bar and the caption stand over `MagicianTall`, and the bar is kept on the stage. No footprint, range or radius follows the measure, and nothing clips a figure: at 1.6 it stands over the curtain at the foot of the back wall and out of the stage's top and sides at a door. The flash is a white copy of the sprite drawn over it, an understudy is the magician's sprite washed with its act's colour, the magician itself is washed pale and part see-through while `MagicianIsInvulnerable` (the Vanish's moment), and a standing figure has a shadow. `art/prompt-guide.md` is the recipe a new figure is made by. What makes a blow felt (flashes, scraps, fading bodies, the shake, the hit-stop, and the cards' effects of plan T22: a flick at a throwing hand, a burst where a card strikes and one where its critic falls, the two bursts sheets played through once; the ring of plan T25's burst card, drawn from the `Burst` event as short stretches round the struck critic's place on the floor, opening to `cardBurstRadius` and dimmer for an understudy's card (`Effect.Ring`, `Effect.UnderstudyRing`); and a puff of scraps at an understudy that gains a card of its act's encores, which no event reports: `Feed` sees that it has more cards than a tick before; the critic that flashes is the one a `Hit` names, kept by its id until its `Kill`; a body lies as the kind it was, which the juice keeps for every critic on the stage by its id, since a `Kill` names a critic that is gone by then; and an understudy's throw is a smaller, dimmer flick in its card's face, `Effect.UnderstudyFlick`, so that the past is told from the present) is the view's own state, in `Juice.cs`: `UnderstudiesGame.Tick` feeds it the simulation after every tick (whatever else the events drive, the sound for one, is fed there too), the frame's time advances it, and the drawing asks it what to add. The capture mode feeds and advances it the same way, a sixtieth of a second a tick. It is advanced in every phase: between two acts the simulation stands and the juice still settles. The shake is a function of the juice's time and draws nothing from `Random`: `ShakesPerSecond` places a second, the same at every frame rate and in a capture. The kill's burst has a pale disc under it for its first half (`KillFlash...`), without which its black ink is lost on the boards. Its numbers are named constants at the top of that file. A figure is drawn by `DrawFigure` alone, which is asked for a flash, a fallen pose and an opacity: nothing paints over a figure with a shape of its own, so the juice holds whatever a figure is drawn from. Text is `FontStashSharp.MonoGame` over the repository's own font files (plan decision 30, T40), in `fonts/` with each family's `OFL.txt`: found as the sprites are (the repository's own when run from its root, the copy the project file puts beside the executable otherwise, the `.ttf` files and the licence texts), and a folder counts only when it has every file of `FaceFiles`, which `Program.cs` checks before a window opens: without one of them the game names it on the console and does not start. There are three faces (`Face`, in the order of `FaceFiles`): `Heading` is Pixelify Sans Bold (a card's name), `Label` is Pixelify Sans SemiBold (a card's head strip: its key and whose it is) and `Sentence` is Atkinson Hyperlegible Regular: every sentence, and every number that is read in a glance (the act's line, the clock, the two counts at the bars, the countdown, what is held, a card's "x5"). The design has those numbers in Pixelify; at the sizes the game has its 5 was read as an S and its 2 as an 8, so they are in Atkinson until the owner says otherwise (plan T40): a new text with a number in it is `Face.Sentence`. Pixelify Sans Regular is in the folder for the one line of the main menu that the design sets in it, and nothing reads it yet. `Write` takes the face first, and `Wide` and `Wrapped` measure in a face. Words are drawn in screen pixels at a size taken from the window, never scaled up from world units, and words on the stage carry an outline in ink (`OutlineInk`, `OutlineWidth`: two screen pixels at 1280 wide and at 1024, and no more than a twelfth of the words' height; `Outline` says how many pixels for a font), drawn by `Write` as the words in ink at every place within that width but the middle and the corners, and then the words; words on paper (a card's panel, dark on light) are written with `onPaper: true` and have none. The outline is outside what `Wide` measures: a layout that sets two outlined texts side by side, or keeps one on the stage, leaves room for it, as the wall's middle line and `keptOnTheStage` do. The library's own stroke is not used: it is black, eats into the letters and moves the line. `ponytail:` Pixelify Sans is smoothed at every size (the comment at `FaceFiles` has why); its squares come nearest to whole pixels at 14 pixels and its multiples, 28 the first that is crisp, so a ticket that sets a size for it picks one that the window makes into those: a card's name is 28 pixels at 1280 wide (`NameHeight`), and the head strip's 21 is left for the ticket that lays the card out again. An understudy is the magician's figure through `DrawFigure`'s `tint` and `opacity`, never a figure of its own. The floor within `applauseBoxOfficeRadius` of the box office is a shade darker with a thin broken line round it (`DrawTheQuietFloor`, first in the batch of what lies flat, kept to the floor; its numbers are constants beside the colours): it is how the player reads where a fall earns no applause. The program's screen is `ProgramScreen.cs`, a second part of the one `UnderstudiesGame` class: the panels, the choosing and the card just taken, for an encore's three cards as for the program's one (`IsOffered` is either). `Update` reads a frame's presses by the phase the frame began in, so one press never does two things: while cards are offered `ChooseInTheProgram` moves the highlight and takes a card (`Take`), and otherwise Space or A is the Vanish and Enter or Start is `GoOn`. Every press there is an edge against `_keysBefore` and `_padBefore`, the stick too, and that is all that keeps a key held since the act from taking a card: an input added to the program must be an edge as well. An encore opens in the middle of a fight, so for its first `EncoreGuardTime` nothing is taken, held or pressed. The view keeps a copy of the offer (`_offered`, made in `Tick` when an encore or a program opens), because `Pick` empties the simulation's: the program's card taken is shown from the copy for `TakenTime`, in which `GoOn` is not called, an encore's is gone at once with the same chime, and an offer that ended inside `Tick` is the clock's pick of the leftmost. The bar on the back wall is the way to the next encore, `EncoreApplause` over `EncoreCost`, with the two numbers beside it. `Describe` is a card as the player reads it (decision 29): its stage name, the sentence that says what one more of it does, with the tuning's numbers filled in and a share as a per cent (for the pierce and the burst, whose copies do not add the same again, the number it would be with this one taken), and its line of flavour, all three the card catalogue's and in code. A panel shows the name fitted to its width, the flavour under it in the smaller face (`FlavourHeight`) and the sentence under that, both broken into lines by `Wrapped`, which measures; how many are held is at the band's right end, and the line of what is held at the bottom edge is broken the same way. A thrown card's trail reaches back to `ThrownCard.ThrownFrom`, so it starts again where a card turned. `Write` draws words in screen pixels from a point of the stage (`_scale` and `_corner` are the frame's), and `Wide` measures them: the back wall's middle line is fitted between the act's line and the clock, smaller when it must be, and a line added to the wall is fitted the same way. R starts a new show through `StartAgain`, which sets back every field the view keeps for one show: a field added for a show is added there. The capture is played by the doors player of the guard: `ScriptedPlayers.cs`, the tests' own file, is compiled into the game as well (a `Compile` link in the project file, so there is one copy), and `Capture` asks it for every tick's input and for which card to take. A card is taken and the next act gone on to before the tick, so neither takes any of a capture's ticks, and a capture that ends on the tick an encore or a program opens shows that screen; the console is told those ticks. Whatever changes that player or what it meets moves the frames: take `art/frames` again in the same change (and `art/frames/s2-design` with `FiguresMeasure` at `1.6f`, until the owner has chosen between the two). Inside this project `Game` means the namespace, so MonoGame's base class is written `Microsoft.Xna.Framework.Game`.
  - the sound is `Sound.cs`, the view's own state like the juice and fed in `Tick` beside it: seven short sounds worked out in code at start-up and handed to MonoGame as `SoundEffect`s (no sound file, no content pipeline), one for each of the event kinds `Throw`, `Hit`, `Kill`, `Vanish`, `BoxOfficeStruck`, `MagicianHurt` and `ApplausePickedUp`. A kind of event that has no sound there is silent. What an understudy did (an event whose `Thrower` is not the magician: its throw, its hit, its kill) plays the same sound quieter and lower (`UnderstudyLevel`, `UnderstudyPitch`), and the magician's own sound is not held back by the gap after an understudy's. How loud each is, the gap between two starts of one sound and every recipe are named constants at the top of that file. A capture makes no `SoundEffect`, so it opens no audio device, and a machine that has none runs the game silent. A sound cannot be reviewed by a captured frame: a changed one is measured by hand (its length, its peak, that it starts and ends at zero: nothing in the repository does it) and then judged by the owner's ear.
- `tests/Understudies.Core.Tests` is NUnit: the rule tests and the scripted players that measure the balance (plan T19, decision 22). `ScriptedPlayers` has the three players, the orbit player, the doors player and the kiter, each a function from the simulation's public surface to one tick's input, with no state and no randomness of its own and Core's arithmetic rule; the one order they pick an encore's card by (`CardOrder`: "one more card", the chorus card, damage, attack speed, then the pierce, the ricochet and the burst, then the longer arm and the quicker Vanish; plan T25 says why the three stand there and not last); and `Play`, which plays a performance to its end, taking every encore's card by that order and a program's card at once, and returns its record act by act. The orbit player is played on three circles (`OrbitRadii`: on the box office, close round it, out where the throw still reaches across), and the design has beaten hiding on a seed only when all three lost: a tuning that beats one circle has beaten a script. The doors player holds the newest door, standing at it (`DoorsPost`: a throw's range in from the door and never more than a third of the way to the box office, so outside `applauseBoxOfficeRadius` at every committed door, which a test holds), fetches applause up to its door and never into the doorway (no further than `DoorsReach` and no further than its post is from its door: the owner's own play, plan T37), steps back from a critic that is upon it, and goes back to the box office while a critic is at it. The kiter (plan T37) is the rival of going out: it walks a circle just outside the radius (`KiterMargin`; a circle of 10 or more is cut by the back wall and its walker crawls), dodges as the doors player does (`Dodge`), and steps out to a piece of applause within `DoorsReach` of its place on the circle but to none that lies nearer an open door than the doors player's post at that door. `Roamer` is the kiter without that bound, which goes out to the doors: it is in the instrument only. A scripted player stands where its script says: before one's counts are believed, look at where it stood (plan T37's first reading was two artefacts). The committed tuning is tuned to the guard (plan T20), and two ordinary tests hold it there, each on the seeds 1 to 20 (a floor of 16) and 101 to 120 (a floor of 14): `TheGuard_..._TheOrbitLosesByActSixAndTheDoorsPlayerFinishesActTen`, which is decision 22, and `..._TheDoorsPlayerDoesBetterThanTheKiter` (it finishes at least as often, with half as many encores again and fifty more of the box office left). Nothing says the kiter loses: by the committed card order it does not, and whether it must is the owner's open question in plan T37. A third ordinary test, on the seeds 1 to 20, is plan T29's two tripwires (`..._TheDoorsPlayerKeepsTheBoxOfficeAndFinishesByAnotherCardOrderToo`): the doors player's box office at the end is at least 350 on average (it is 392; the guard's own floor of 16 finished would let it fall to 320 unseen), and by "range first" (`RangeFirst`) it still finishes on at least 16 of 20 (it does on 20 since plan T25, on 18 before). A tuning is read by more than one card order before it is believed: T29's first numbers (a rival of 150 hit points from act seven) held by the committed order and lost act seven on every seed by any other, and `PrintTheVariants` now prints the doors player and the kiter by "range first" and by "one more card last" under every variant. By "one more card last" nobody finished on T29's numbers (14 of 20 did before the rival) and since plan T25 both players finish every seed, the three new cards standing in for it: that is measured and not asserted. A change to `tuning.json`, to a rule or to a player that breaks either test is a finding about the design, not a number to loosen. The seeds have a rule (plan T37, "What the guard measures and what it does not", which is to be read before tuning to the guard): numbers are searched on 1 to 20 only, 101 to 120 is read once on the candidate, and 301 to 320 only for the last check of a tuning (201 to 220 is spent: T29's review read it). The guard's performances are played once for all its tests (`TheGuard`, a `Lazy` for each set). `PrintTheGuardsTable` plays all three players on the seeds 1 to 20 and prints how each performance ended, act by act with each act's applause and encores, and the guard's counts; `PrintTheVariants` (`[Explicit]` too) is the instrument of plan T26: for every variant of the committed tuning in the file the environment variable `UNDERSTUDIES_VARIANTS` names (a line each, `name | { "key": value }`), on the seeds 1 to 20, the guard's counts, how and in which act each player lost (the magician up or down), and by act the encores, the applause, the box office and the most critics at once; beside the guard's players, the kiter among them, it plays the doors player with no applause in act one and the orbit on circles of 9 and 13, which count for nothing in the guard (and are cut by the back wall), and the roamer; for every player but the orbit it prints by act the share of the magician's own kills that fell within 3, 5 and 8 seconds of entering (`ActRecord.Kills` and its three counts, made in `Play`). It plays the seeds 1 to 20 alone unless `UNDERSTUDIES_SEED_SETS` names the sets by their first seeds (`1,101`, `201`). `PrintTheCardOrders` (`[Explicit]`) plays the doors player and the kiter by eleven orders of taking cards (the committed one, its reverse, "one more card" last, the longer arm first, each of plan T25's three cards first, each of them in the place of "one more card", which is then last, and the three last, which is also played with the three made to do nothing: the order T25 was asked for and why it was not taken): `Play` and `Choose` take an order, the committed `CardOrder` when none is given. A change to `tuning.json`, to a rule or to a player changes them: pin the numbers again from the failure's message and say so in the pull request. It changes what a capture shows too: take `art/frames` again. If the two machines ever disagree, do not make it pass: keep a pin for each machine and tell the owner. Every act opens with a curtain in which `Step` only counts the curtain down, so a test scene that counts its ticks from the first tick of an act sets `CurtainTime = 0f` in its own tuning (no curtain); `CurtainTests` are the ones with a curtain.
- `tuning.json` is copied by the project files beside the tests and beside the built game. The tests read that copy through `CommittedTuning`, so a test never carries its own numbers. The game reads `tuning.json` in the current directory first (the committed file itself, as commands run from the root) and the copy beside the executable otherwise; F5 reads it again while the game runs.

## How the work runs

- One ticket of `docs/plan-prototype.md` is one branch (`tNN-short-name`) and one small pull request into `main`, whose title starts with the ticket id (`T04: ...`). Tickets are taken in order.
- Work in a git worktree; the owner's checkout stays on `main`.
- Write the test first for every rule in Core. The view and the juice have no tests: they are judged by eye at the plan's stops, and by a captured frame in review.
- Before a merge, a separate agent with a clean context reviews the pull request with the `mattpocock-skills:code-review` skill (fixed point `main`; the spec is the ticket in the plan) and the `ponytail:ponytail-review` skill. Fix or answer what it finds, wait for green CI, then merge.
- The plan's stops are where the owner plays and judges. The loop does not wait at a stop: it announces it and goes on.
- Build the smallest thing the ticket asks for: no abstraction, option or layer for a later ticket. Mark a deliberate shortcut that has a known ceiling with a `ponytail:` comment naming the ceiling.
- Everything in the repository is in English. There is no study journal in this project.
